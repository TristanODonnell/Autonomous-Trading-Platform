# Platform Backtest Output Audit

**Purpose:** Determine what performance metrics, outputs, events, telemetry, and results should be surfaced after a full platform backtest — and identify what is currently missing.

A **platform backtest** is the complete autonomous investing platform (`PlatformBacktestRunner`) operating over historical market data. It is invoked via:

```
atp platform backtest run --fixture <fixture.yaml> --start 2024-01-01 --end 2024-12-31
atp platform backtest report --artifact artifacts/platform/backtests/<bundle>.json
atp platform backtest inspect --artifact <bundle>.json --section portfolio
```

The runner orchestrates a full tick loop:
> preflight → settings snapshot → controls snapshot → safety snapshot
> → FOR EACH trading day: ingestion → corporate actions → features → universe → trading cycle → risk → governance → portfolio snapshot → research → operations
> → final domain summaries → artifact bundle

This is distinct from research `SimulationRun` objects (per-strategy backtests generated by the research pipeline). Platform backtest results are about the full autonomous system, not individual strategy validation.

The primary question this document answers:
> **"Did the autonomous investing platform perform well, and why?"**

### 1.2 What Each Section Currently Contains

#### `runtime` — `RuntimeSummary` (line 237)
```
ticks_attempted, ticks_ok, ticks_failed
total_orders, total_fills

```
Operational completeness. Does not include any performance metrics.

#### `portfolio` — `PortfolioSummaryBundle` (line 267)
```

cash_balance (str)        — final cash
invested_capital (str)    — final invested capital
open_positions (int)      — count of open positions at end

```
Populated by `build_portfolio_summary` → `PortfolioSummaryService.get_summary()`.
**`PortfolioAnalyticsService.get_performance()` and `.get_risk()` are not called here.**

#### `risk` — `RiskSummary` (line 247)
```
gross_exposure (str)               — end-state gross exposure
net_exposure (str)                 — end-state net exposure
drawdown_pct (float)               — drawdown at the final tick

block_reasons (list[str])          — end-state block reasons
drawdown_ladder_states (dict)      — per-strategy ladder state at end
budget_mode (str)                  — risk budget mode in use
```
This is a **snapshot of the final state**, not a time-series or aggregate. Max drawdown over the entire run is not here.

#### `governance` — `GovernanceSummary` (line 258)
```

promotions_executed (int)
demotions_executed (int)
health_transitions (int)
```

Cumulative totals over the run. No event log, no per-strategy breakdown, no timestamps.

#### `execution` — `ExecutionSummary` (line 313)
```

```
`reconciliation_status` and `policy_mode` are always `None`. Slippage, fill latency, and cost statistics are not computed.

#### `research` — `ResearchSummary` (line 322)
```
experiment_id (str)
total_runs (int)
passed_filters (int)
run_timestamp (str)
```
Reflects only the most recent scheduled research tick. Not an aggregate over the full run.

#### `strategy_catalog` — `StrategyCatalogSummary` (line 339)
```
total_active (int)
paper_count (int)
live_count (int)
strategy_types (list[str])
```
Final-state catalog snapshot only.

#### `tick_results` — Per-Tick Domain Results
Each entry in `tick_results` contains the `summary` dict from every domain hook that ran on that trading day:
- `ingestion`: dataset_version_id, symbols_ingested, missing_bar_incident_count, rows_written
- `features`: features_computed, features_reused, lineage_ok
- `universe`: symbol_count, rotation_applied, churn_pct
- `trading`: orders_submitted, fills_received, cycle_blocked, block_reason
- `risk`: risk_snapshot_id, is_blocked, block_reasons, drawdown_pct
- `governance`: strategies_evaluated, promotions_executed, demotions_executed, health_transitions
- `portfolio`: portfolio_value, cash_balance, open_positions (per-tick)
- `research`: experiment_id, total_runs, passed_filters
- `operations`: system_health_status, active_alerts_count, critical_alerts_count

The `tick_results` list contains the full time-series history. **`portfolio.portfolio_value` appears every tick, making a daily equity curve derivable from the artifact.**

## 3. Benchmark Comparisons

### 3.1 Required Benchmarks

| Benchmark | Why It Matters | Required Comparisons |
|---|---|---|
| **S&P 500 (SPY)** | Standard equity market baseline. Did the platform beat the obvious passive alternative? | Excess return, Sharpe delta vs SPY Sharpe, max drawdown vs SPY drawdown |
| **Buy-and-Hold Equal Weight** | Isolates active selection value. Did the platform's strategy selection and allocation add anything vs just holding the same symbols equally? | Alpha, Information Ratio |
| **Cash / Risk-Free Rate** | Floor check. Did the platform beat doing nothing? | Absolute return above risk-free |
| **Target Return (configurable)** | Answers whether the platform met its stated investment objective. | Actual CAGR vs target (10% / 15% / 20%) |

### 3.2 What's Currently Missing for Benchmarks

Neither the artifact nor the database contains benchmark return data. To support benchmarks:
- Benchmark daily returns must be ingested and stored alongside the backtest date range
- A `BenchmarkReturnRow` or equivalent must be added to the SOR
- `Information Ratio = (strategy_return − benchmark_return) / tracking_error` — requires both

## Appendix: Key CLI Commands

```bash
# Plan a backtest (validate without running)
atp platform backtest plan --fixture fixtures/my_backtest.yaml

# Run the full platform backtest
atp platform backtest run --fixture fixtures/my_backtest.yaml --output artifacts/platform/backtests/run.json

# Dry run (validate plan only, no mutations)
atp platform backtest run --fixture fixtures/my_backtest.yaml --dry-run

# Run with failure injections from fixture timeline_events
atp platform backtest run --fixture fixtures/my_backtest.yaml --inject-failures

# Inspect a saved artifact (all sections)
atp platform backtest inspect --artifact artifacts/platform/backtests/run.json

# Inspect a specific section
atp platform backtest inspect --artifact run.json --section portfolio
atp platform backtest inspect --artifact run.json --section governance
atp platform backtest inspect --artifact run.json --section risk

# Find artifact by run_id
atp platform backtest inspect --run-id <replay_id>

# Generate summary report
atp platform backtest report --artifact run.json

# Dashboard snapshot (calls PortfolioAnalyticsService — the richer data source)
atp platform dashboard-snapshot --output artifacts/dashboard.json
```
