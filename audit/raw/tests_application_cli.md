## Notable test infrastructure

- **Fail-fast negative-invariant pattern reused across many CLI files**: monkeypatching a dependency (broker client `__init__`, `Settings()`, a scheduler cycle function) to `pytest.fail(...)` or raise `AssertionError` if called, then asserting the code path under test never reaches it. Used to prove: dry-run never executes the live cycle (ingestion, features, runtime evaluate-cycle), local-only diagnostics never construct a broker client, offline policy-preview never touches broker `Settings`, and safety commands never accidentally create singleton DB rows. This is a much stronger guarantee than asserting on output alone.
- **"JSON mode must be pure JSON with no header noise" is a recurring explicit test** across `test_admin.py`, `test_diagnostics.py`, `test_runtime_governance_jobs.py` — asserting `out.lstrip().startswith("{")` and that plain `json.loads(out)` succeeds without stripping a human-readable header first.
- **Real Parquet I/O** is exercised in `test_features.py::test_sample_dataset_reads_small_parquet_sample` via `pyarrow.parquet.write_table` — one of very few places in this scope touching the filesystem/Parquet layer rather than just SQLAlchemy.
- **Numerical rigor in application/services**: several files assert against hand-derived closed-form values rather than just "greater than" checks — e.g. `test_risk_budgeting_service.py`'s portfolio-vol-annualization (`daily_vol/√2 * √252`), `test_metric_lineage_service.py`'s exact blended-score formula (`0.10*live + 0.90*research`), and `test_optimization_backend.py`'s covariance-repair metadata.
