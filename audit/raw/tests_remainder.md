## tests/conftest.py (287 lines) — FULL DEPTH

Root fixture file, loaded for the entire suite.

- **Env vars set via `os.environ.setdefault`** (lines 58-64) BEFORE any app import: `APP_ENV=test`, `DATABASE_URL=sqlite:///:memory:`, `TRADING_ENVIRONMENT=paper`, `NO_LIVE_TRADING=true`, `SHADOW_MODE_ENABLED=false`, `JWT_SECRET=test-secret-do-not-use-in-prod-1234`, `JWT_ALGORITHM=HS256`. **Confirmed** — matches claim (2).
- **SQLite compatibility shims** (lines 72-85), patched onto `sqlalchemy.dialects.sqlite.base.SQLiteTypeCompiler` before models import so `create_all()` sees them:
  - `visit_JSONB` → delegates to `visit_JSON(JSON())`
  - `visit_ARRAY` → delegates to `visit_TEXT(Text())` (stored as JSON string, DDL-only fidelity)
  - `visit_UUID` → delegates to `visit_VARCHAR(String(36))`
  **Confirmed** — matches claim (1) exactly; comment in-file explicitly states "Must be patched BEFORE any app models are imported."
- Single shared in-memory SQLite engine (`sqlite://` + `StaticPool`, `check_same_thread=False`) — same connection reused across the whole session so `:memory:` doesn't vanish between fixtures.
- `create_tables` fixture: session-scoped, autouse, runs `Base.metadata.create_all(bind=_engine)` once.
- `db_session` fixture: opens a connection, begins outer transaction + nested SAVEPOINT, uses `after_transaction_end` listener to restart the savepoint after nested commits (standard "transaction rollback per test" isolation pattern) — every test gets a clean rollback-able session without re-creating tables.
- `client` fixture: builds a real `create_app()` FastAPI app, overrides `get_session` dependency to yield the test's `db_session`, returns `TestClient(app, raise_server_exceptions=True)` — exceptions inside route handlers propagate to the test rather than becoming 500 JSON, meaning `tests/interfaces/rest/*` tests exercise real app wiring (real middleware stack, real routes) against a real (SQLite) DB, not a fully mocked app.
- JWT helpers `make_token(role, sub)` / `auth_headers(role)`: sign real HS256 JWTs with the test secret — matches app's real JWT middleware, so interface tests do real auth round-trips, not mocked auth.
- `seed_strategy_governance` helper: inserts a `StrategyGovernance` row directly via ORM.
- 8 fixture wrappers (`seeded_paper_trading_cycle_fixture`, `seeded_paper_trading_golden_path_fixture`, `seeded_market_ingestion_cycle_fixture`, `seeded_feature_pipeline_cycle_fixture`, `seeded_corporate_action_ingestion_cycle_fixture`, `seeded_market_backfill_cycle_fixture`, `seeded_historical_research_golden_path_fixture`, `seeded_experiment_pipeline_cycle_fixture`) — each thin wrapper injects `db_session`, `tmp_path`, `monkeypatch` into a builder function imported from `tests/utilities/*.py`. **This confirms exactly 8 scenario-builder fixtures wired into conftest** — matches claim (3) that there are 8 (see tests/utilities section below for the builder implementations themselves).

## tests/utilities/ (10 files, 2066 LOC, 0 direct tests — scenario-builder library) — FULL DEPTH

Confirms claim (3): **exactly 8 scenario-builder fixtures**, each wired into `conftest.py` and each following the same shape: `_seed_environment` (monkeypatch env vars) → `_patch_runtime_seams` (monkeypatch.setattr on real production module attributes: `get_session`, broker/data clients, universe readers) → optionally write Parquet fixture data via the real `write_table`/`dataset_version_root` machinery → seed Postgres-shaped rows via the real SQLAlchemy ORM models (`session.merge`) → return a frozen dataclass of fixture constants for assertions. None of these mock the ORM or Parquet layers themselves — they monkeypatch only the I/O boundary (broker client, data-provider client, `get_session` lookup used inside scheduler cycle modules) and let real service/repository code run against the SQLite session and real (tmp_path) Parquet files. This is "integration-style" fixture design even though it runs under the unit-test SQLite DB.

1. **`factories.py`** (403 lines, not a scenario builder — flat Pydantic-contract factories) — `make_universe_snapshot`, `make_universe_version`, `make_universe_member`, `make_market_bar` (+ `make_minute_bar`/`make_five_minute_bar` wrappers that resolve `BarInterval` enum members defensively via `hasattr` probing across naming variants — defensive coding smell suggesting enum member names were unstable during development), `make_fill`, `make_raw_market_symbol`, `make_raw_market_pool_snapshot`, `make_raw_market_pool_membership`, `make_order_intent`. All are pure keyword-arg builders around real Pydantic contracts with sensible defaults (fixed UUIDs/timestamps) for deterministic tests.

2. **`paper_trading_cycle_fixture.py`** (547 lines) — builder **#1**. Largest/most detailed builder. Defines `FakePaperBrokerClient` (full broker interface stub: get_account/get_positions/get_latest_trades/submit_order/get_order_by_id/list_open_orders/cancel_order/close, all in-memory, deterministic fills). `seed_paper_trading_cycle_fixture` sets 12 env vars (`NO_LIVE_TRADING=true`, `ENABLE_LIVE_TRADING=false`, `INCLUDE_LIVE_MODULES=false`, `PAPER_ALLOWED_ACCOUNT_IDS`, etc.), monkeypatches `AlpacaBrokerClient → FakePaperBrokerClient`, `UniverseMembershipReader.get_symbols_for_timestamp`, and `StrategyEvaluationService.evaluate` (forced deterministic BUY signal), writes 301 five-minute adjusted SPY bars + a feature-returns Parquet dataset via the real writer, then seeds `DatasetVersions`, `FeatureDatasetVersions`, `SymbolDateCoverage`, `StrategyConfigs`+`StrategyGovernance`+`StrategyRuntimeState` (x2 strategies), `CapitalAllocationPolicies`, `CashSnapshot`+`PositionSnapshot`+`PositionSnapshotItem`, `RuntimeControlState` (kill_switch_enabled=False, trading_enabled=True), and a `UniverseVersion`/`UniverseMember` row — i.e., an almost-complete paper-trading-ready DB state for one full runtime cycle.

3. **`paper_trading_golden_path_fixture.py`** (77 lines) — builder **#2**, a composition layer: chains ingestion + corporate-action + feature-pipeline runtime-seam patches, then calls `seed_paper_trading_cycle_fixture` and re-wraps its result. This is the "golden path" (multi-stage pipeline → paper trading) scenario.

4. **`market_ingestion_cycle_fixture.py`** (188 lines) — builder **#3**. Defines `FakeOneMinuteMarketDataClient`/`FakeProviderBar` producing 5 fake 1-min bars per symbol for 250 fake symbols (`TST0000`..`TST0249`), designed so 5x1-min bars aggregate into one 5-min bar (tests the aggregation path). Monkeypatches `get_data_root`, `Settings.DATA_ROOT`, `cycle_module.get_session`, `UniverseMembershipService.get_query_symbols_for_date`, `fetch_minute_bars` (two locations), and `BarValidationService.is_late_bar → False`.

5. **`feature_pipeline_cycle_fixture.py`** (225 lines) — builder **#4**. Writes 250 days x 2 symbols (SPY, AAPL) of daily raw bars to Parquet, seeds `DatasetVersions` + `SymbolDateCoverage` rows (needed for pipeline completeness guards), patches `get_session`/`get_data_root`/`Settings.DATA_ROOT`.

6. **`corporate_action_ingestion_cycle_fixture.py`** (129 lines) — builder **#5**. Defines `FakeIngestCorporateActionsJob` (no-op), patches `generate_dataset_version` with a deterministic counter-based fake, patches `IngestCorporateActionsJob`, seeds one `DatasetVersions` row for a raw-bars source dataset.

7. **`market_backfill_cycle_fixture.py`** (155 lines) — builder **#6**. Defines `FakeAlpacaHistoricalBarsClient.fetch_bars` (10 fake bars/symbol for SPY/AAPL/MSFT), patches `get_stock_historical_client` and `AlpacaHistoricalBarsClient`, plus the standard `get_session`/data-root patches. Explicitly clears `DATA_ROOT`/`PARQUET_DATA_ROOT`/`LOCAL_DATA_ROOT` env vars first, then resets them to `tmp_path` — guards against real filesystem paths leaking in from the environment.

8. **`experiment_pipeline_cycle_fixture.py`** (239 lines) — builder **#7**. Defines `FakeStage` (a minimal `BaseStage` implementation), `FakeExperimentOrchestrationService` (records `run_experiment`/`run_staged_experiment` calls, can be configured to raise), `FakeSimulationContext`. Builds two real `ExperimentDefinition` contract instances (a non-staged SWEEP and a staged SWEEP with `StagedPipelineConfig(stages=[FakeStage()])`), patches `build_simulation_context` to return the fake context. Also exports `EXPERIMENT_YAML_CONTENT` (a raw YAML string) for tests that exercise YAML-driven experiment loading.

9. **`historical_research_golden_path_fixture.py`** (112 lines) — builder **#8**, the deepest composition: chains backfill + corporate-action + feature-pipeline + experiment-pipeline runtime-seam patches together and constructs one more `ExperimentDefinition` — models the full "historical research" golden path from raw backfill through to a strategy experiment.

10. **`tests/utilities/__init__.py`** — empty, package marker.

**Assessment:** this is genuine, non-trivial test infrastructure — not boilerplate. The 8 builders form a layered composition graph (ingestion → corporate actions → features → experiments/paper-trading → golden paths compose the atomic cycle fixtures), each monkeypatching real production seam points (module-level `get_session` lookups, broker/data-provider clients) rather than mocking business logic, and each writing through real Parquet writer + real ORM merge calls. This lets `tests/runtime/`, `tests/safety/`, and (likely) other suites exercise multi-service "cycle" scenarios (a full ingest→feature→trade loop) against SQLite + tmp_path without touching Postgres or Alpaca.

Pure unit tests, zero I/O, zero mocking — these test the declarative business-rule layer (`contracts/validators/`) independent of persistence.

Decimal NaN, `is_non_negative`, `is_positive`, `is_aligned_to_minutes`, `run_rules` success/violation paths, and a rule whose check raises an exception gets wrapped as `VALIDATOR_EXCEPTION::<code>` rather than crashing the run — fail-safe design).

## tests/feature_engineering/ (8 files, 623 LOC, 45 tests) — one line per file

Statistical/numeric unit tests for the regime-classification feature layer. All use `numpy.random.default_rng(seed)` for determinism, synthetic OHLCV/returns DataFrames (no DB, no fixtures, no mocking) and a recurring `test_deterministic` test (`pd.testing.assert_frame_equal(r1, r2)` on two calls with identical input) plus a `test_missing_required_column_raises` guard-clause test, per classifier.

- `tests/feature_engineering/__init__.py`, `tests/feature_engineering/regimes/__init__.py` — empty package markers.
- `test_liquidity_regime_classifier.py` (99 lines, 7 tests) — `LiquidityRegimeClassifier`: output-column presence, warmup-bar nulls (first `avg_window-1` rows NaN), high/low liquidity correctly triggered by synthetic high/low dollar-volume regimes, confidence bounded [0,1], determinism, missing-column `ValueError`.
- `test_mean_reversion_regime_classifier.py` (110 lines, 6 tests) — `MeanReversionRegimeClassifier`: synthetic mean-reverting (Gaussian noise around fixed mean) vs. trending (linear drift) price series correctly differentiate `MEAN_REVERTING` vs. non-MR label dominance, confidence bounds, determinism, missing-column guard.
- `test_regime_classification_feature_service.py` (62 lines, 6 tests) — `RegimeClassificationFeatureService` (feature-job adapter layer): returns a DataFrame, output has all 5 regime columns (`regime_trend`/`volatility`/`liquidity`/`mean_reversion`/`risk`), row count preserved, determinism, missing `symbol` column raises, custom window parameters forwarded correctly.
- `test_regime_classification_service.py` (126 lines, 11 tests) — `RegimeClassificationService` orchestrator: full 20-column output schema check, row-count match, determinism, **cross-regime composition logic** — asserts `regime_risk == RISK_ON` whenever `trend==BULL and volatility==NORMAL`, and `regime_risk == RISK_OFF` whenever `trend==BEAR and volatility==HIGH` (conditional assertions, only checked when such rows exist in the synthetic sample — could silently no-op if the synthetic data never produces the combination), inline-vs-external returns_frame equivalence, multi-symbol independence (AAPL uptrend / MSFT downtrend classified independently in one combined call).
- `test_trend_regime_classifier.py` (126 lines, 9 tests) — `TrendRegimeClassifier`: monotonic uptrend → mostly `BULL` (>80% of non-warmup rows), monotonic downtrend → mostly `BEAR`, sinusoidal flat series → some `SIDEWAYS` labels, warmup-null region matches `long_window-1`, confidence bounds, determinism, missing-column guard, multi-symbol independence.
- `test_volatility_regime_classifier.py` (105 lines, 8 tests) — `VolatilityRegimeClassifier`: calm-then-volatile synthetic returns correctly flip to `HIGH_VOLATILITY` in the spike window, very-tight returns yield `LOW_VOLATILITY`, warmup nulls, confidence bounds, determinism, missing-column guard, and `volatility_threshold_high >= volatility_threshold_low` invariant.

No integration with the `RegimeClassification*` services' Parquet/DB persistence path is tested here — this directory is pure numerical-logic unit testing of the classifiers/orchestrator in isolation.
