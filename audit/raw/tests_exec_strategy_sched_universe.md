## Test quality assessment

- **Order lifecycle / fills / ledgers — numeric AND scenario-based, extensively.** `test_order_state_machine_service.py` walks the full VALID_TRANSITIONS matrix (every status×event pair) plus an 18-case invalid-transition matrix and a terminal-state × all-events cross-product — the strongest state-machine coverage in the repo. `test_broker_order_mapper.py` and `test_order_runtime_state_service.py` both enforce the F-05 monotonic-fill-qty guard (stale/regressed updates blocked + logged, never rewound). `test_cash_ledger_service.py`, `test_position_ledger_service.py`, `test_reserved_cash_lifecycle.py`, and `test_settlement_cash_ledger.py` all do hand-computed arithmetic (avg-cost recompute, realized P&L, reserved-cash floor-at-zero, `settled_cash + unsettled_cash == cash` invariant asserted in nearly every case) plus full round-trip reserve→partial-fill→carry-forward→final-fill integration tests.
- **Kill-switch / drawdown gating tested end-to-end, not just at the unit boundary.** `tests/execution/test_portfolio_drawdown_governance_service.py` (~40 tests) covers breach detection, all four actions (WARN_ONLY/PAUSE_NEW_TRADING/PAUSE_REBALANCING/ACTIVATE_KILL_SWITCH) in isolation, and a full breach→pause→acknowledge→resume→re-breach lifecycle, with a fake `KillSwitchService` asserting `.enable()`/`is_enabled()` are actually called. `tests/scheduler/test_paper_trading_cycle.py` goes one level higher and drives the **real** `run_trading_cycle` against kill-switch / trading-paused / trading-disabled / mode-mismatch / per-strategy-disabled states, asserting zero downstream artifacts (no intents/fills/positions) and a `skip_reason` recorded on both manifest and job output for each — this is the best evidence of true end-to-end safety-gate coverage in the audited scope.
- **Signals tested against known/hand-computed values, not just "returns something."** All five `tests/strategy/indicators/` files (momentum, trend, volatility, volume, mean_reversion) verify golden numeric outputs (e.g. RSI mixed gains/losses → exactly 80.0, EMA multi-step hand-traced, sample-variance n-1 check). `tests/strategy/test_indicator_feature_equivalence.py` cross-validates strategy-layer indicators against the offline `feature_engineering` services with `pytest.approx` on real DataFrames — a high-value drift check between live and backtest math that would otherwise go unnoticed.
- **Universe rotation atomicity/rollback: partially tested, with a real gap.** The *business*-level rollback operation (`UniverseRotationService.rollback()`) is well covered in `test_universe_rotation_service.py::TestRollback` (creates+activates a rollback version, retires current active, persists a rotation record with `rollback_reason`, raises for missing/empty target). Immutability *enforcement* is tested against a real SQLite session in `test_universe_version_repository_immutability.py` — cannot insert a version pre-set to ACTIVE, cannot activate with zero members, cannot insert members into an already-active version (`ImmutableVersionError`), invalid RETIRED→ACTIVE transition raises. However: `test_universe_rotation_service.py` exercises `rotate()`/`rollback()` exclusively against **hand-written in-memory stub repositories** (`StubVersionRepo` etc.), not a transactional DB session — there is no test in this scope verifying true **atomicity on partial failure** (e.g., a rotation record insert raising *after* `activate_version` has already flipped the previous version to ACTIVE). The rebalance hysteresis/churn algorithm itself (`test_universe_rebalance_service.py`, 52 tests) is exceptionally thorough on the numeric/scenario side.
- **Exact skip/xfail inventory (repo-wide within this scope):** exactly **2** `pytest.skip()` calls, both in `tests/strategy/test_strategy_registry_parameter_integration.py` (lines 29 and 68) — both skip the `composite_rule` strategy type because it uses a structured nested config rather than flat parameter fields, not because of a known bug. **0** `xfail` markers anywhere in `tests/{execution,strategy,scheduler,universe}`.
