## Test quality assessment

The suite is overwhelmingly **numeric and behavioral**, not shallow existence-checking. Representative evidence:

- **Look-ahead / survivorship guards are directly tested, not just exercised incidentally.** `tests/research/simulation/test_lookahead_guard.py` unit-tests `LookaheadGuardService.assert_historical_only` (rejects current/future bars, raises on unsorted/duplicate timeline) and the `StrategyContextBuilder` integration point. `tests/research/simulation/test_simulation_execution_engine_golden_path.py`'s `TestNextOpenFillSemantics` class hand-constructs OHLC fixtures to prove fills land at bar N+1 open, never the signal-bar close. `tests/research/regimes/test_regime_join_service.py::test_no_lookahead_bias_exact_join_only` explicitly asserts the regime join uses exact-timestamp matching only (no forward-fill). `tests/research/validation/test_survivorship_validation.py` directly tests `SurvivorshipValidationService` detecting leaked future symbols with exact counts.
- **Black-Litterman math is tested numerically**, not just smoke-tested: `tests/research/test_black_litterman_research_service.py::test_implied_prior_return_calculation` verifies the CAPM-style implied-prior formula via `np.testing.assert_allclose(prior, risk_aversion * cov @ benchmark)`; posterior/weight computation is checked for constrained weights summing to exactly 1.0, deterministic hashing of inputs/views/outputs, and infeasible-constraint/invalid-view rejection paths.
- **Execution-realism numerics are dense and precise**: slippage formulas verified against hand-computed `Decimal` expected values (`test_volume_share_slippage_model.py`, `test_spread_aware_slippage_model.py`, `test_simulator_slippage.py`), settlement/reserved-cash/dividend accounting invariants (`cash == settled + unsettled`, `equity == positions_value + settled_cash + unsettled_cash`) checked at every bar across three dedicated files, deterministic-replay regression gates (`test_deterministic_replay.py`, explicitly documented as a "CI regression gate") assert byte-identical equity curves/trade logs/fill IDs across reruns.
- **Weakest spots**: `test_strategy_clustering.py::test_parameter_spam_flagged_for_low_variance_cluster` has a vacuous `any(...) or True` assertion (always passes regardless of behavior); `test_reproducibility.py::test_determinism_contract_documented` is an explicit `assert True` documentation marker; `test_settlement_simulation.py` has several maturation-dependent assertions gated behind `pytest.skip` that aren't guaranteed to execute depending on the constructed price path; some observability tests (`test_cache_observability.py`, `test_checkpoint_observability.py`, `test_parallel_execution_metrics.py`) mock the OTel counter/histogram objects directly rather than asserting on real exported metrics, which is appropriate for unit-level isolation but means the tests verify "was `.add()` called" rather than end-to-end metrics correctness.

## Notable test infrastructure

- **Zero Postgres/network dependency**: no `integration`, `external`, `alpaca`, `smoke`, or `paper_runtime` markers anywhere in the suite — every test runs as a fast in-process unit test, many using `tmp_path` for real Parquet I/O instead of mocking the filesystem.
- **Capturing test doubles over raw mocks** are used pervasively for behavioral assertions: `CapturingSimulationRunner`, `CapturingRecorder`, `CountingRunner` classes record actual call arguments rather than relying solely on `Mock.assert_called_with`, enabling assertions like "every MC trial got a unique `mc_run_N` window_role" checked against real captured data.
- **Deterministic-seed engineering is a first-class test target**: `DeterministicSeedService`, `_init_rng` isolation from global `random` state, and UUID5-based deterministic child-order IDs (TWAP/VWAP slicing) all have dedicated determinism tests, reflecting that reproducibility is treated as a hard platform invariant, not an afterthought.
- `tests/research/test_research_hooks_smoke.py` is a genuine end-to-end integration test (real Parquet files written via `tmp_path`, real SQLAlchemy session, real dataset-version SOR row) exercising the full monthly research pipeline in a few seconds — unusual thoroughness for something labeled a "smoke test."

## Gaps

- **No load/property-based testing**: numeric bound-checking (e.g. partial-fill fraction bounds, participation-cap enforcement) relies on fixed seed ranges (e.g., "loop over seeds 0-200 until a rejection occurs") rather than Hypothesis-style property tests — works but is a bit brittle/slow if underlying RNG behavior ever changes.
- **`research/strategy_generation/` is thin**: only one test file (`test_generation_engine.py`) covers the entire strategy-generation subsystem (grid/random/evolutionary/composite generators, parameter-space resolver) — no dedicated tests for individual generator classes in isolation beyond what's exercised through the engine.
- **OTel observability tests mock the metrics objects themselves** rather than validating exported metric values end-to-end through a real exporter/collector — acceptable for unit isolation but leaves a gap in verifying metrics are correctly wired into the actual OTel pipeline.
- **Settlement/dividend maturation edge cases are conditionally skipped** (5 `pytest.skip()` calls) rather than using fixtures engineered to guarantee the scenario fires every run.
